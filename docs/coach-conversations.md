# Coach conversations and student notifications

Students open Learning Coach and select **+ New session** to start a separate conversation. The conversation buttons reopen saved messages. **Previous conversations** preserves messages created before thread support. A thread is scoped to the signed-in user, organization and course; an unknown or foreign thread returns 404. Thread IDs also separate ADK session identities. Changing conversations is disabled while a reply is running.

Starting a conversation clears conversational history, but keeps academic context and the student/course Memory Bank scope. The Coach receives the Learning Twin, available tests, recent assessment attempts, visible coding assignments, the student's repository reports and assigned learning plans. Assessment scores respect feedback release settings. Exam questions and answer keys are excluded. Context includes up to six recent conversation turns, 30 assessment attempts and 20 repository reports; it is not an unlimited archive. Repository ratings remain provisional.

Coach, Classroom Advisor, learning-plan prose and coding summaries share Markdown rendering. Python indentation is preserved in copyable fenced blocks; tables scroll on small screens. Raw HTML and remote images are disabled, and links allow HTTP/HTTPS only. Shared agent instructions ask for concise explanations, focused examples and accurate distinctions between conventions and runtime guarantees. Structured assessment output still follows its JSON schema.

The notification bell is available to both students and teachers. Student events include published/assigned tests, new coding assignments, completed coding reports, assigned learning plans and evidence-based Coach review recommendations. Draft tests and unassigned plans do not notify students. Notifications persist in PostgreSQL, are recipient scoped and deduplicated by event, target and recipient. Opening an update marks it read and navigates to the relevant class/page. New events show a popup while the application is open; the feed polls every eight seconds and refreshes when the tab becomes visible. This is an in-app service, not email or background browser push.

Coach review recommendations are deterministic: after assessment evidence updates, concepts classified as `requires review` generate an actionable notification. They do not create assignments, invent grades or automatically generate another test. Agent completion producers use the shared `backend/notifications.py` service.

API: `GET/POST /api/courses/{course_id}/coach-sessions`, `GET /api/courses/{course_id}/chat?conversation_id=...`, and `POST /api/courses/{course_id}/chat` with `conversation_id`. Omitting the conversation ID accesses the previous conversation history for backward compatibility. The student navigation hides Agents & sessions; its diagnostic API is teacher-only.

## Live response progress

Coach and Classroom Advisor messages display their sent/reply times in the viewer's local timezone. Hovering over a time shows the full date, time and timezone. New exchanges store separate server timestamps (`question_at`, `response_at`) and response preparation duration (`duration_ms`) in PostgreSQL; replies also show **Took ...s**. Preparation duration includes record retrieval, optional memory lookup and reasoning, before conversation persistence. Both interfaces restore timestamps from saved history. Legacy replies use their existing `at` timestamp; legacy questions without a sent timestamp show **Time unavailable** rather than an invented time.

Coach and Advisor use `POST /api/courses/{course_id}/chat/stream`, an authenticated fetch stream of Server-Sent Events. The backend emits `progress` events when it begins reading the learning record, looking up Memory Bank (if requested and enabled), preparing the response, and saving the conversation. Skipped memory lookups do not appear. Earlier steps display as complete when the next stage starts. These are coarse application stages, not model chain-of-thought, individual tool traces or token streaming.

A `result` event carries the validated complete answer; an `error` event carries a safe message and status. Heartbeats keep the connection alive during longer stages. The UI supports cancellation and a two-minute request timeout, preserving explicit errors for interrupted streams. The original JSON chat endpoint remains available. Proxies must allow streaming without buffering; the response sends `Cache-Control: no-cache` and `X-Accel-Buffering: no`. Browser behavior through a deployed cloud proxy has not yet been verified.
